# To Vowelize or Not? Inference-Time Diacritization for Zero-Shot Saudi Arabic TTS

Data, code and per-clip results for the paper *"To Vowelize or Not? Inference-Time Diacritization for Zero-Shot Saudi
Arabic Text-to-Speech"* (Amr Abdelkhalik, 2026).

We test whether adding automatic diacritics (tashkeel) in front of six open zero-shot TTS models helps or hurts
intelligibility for Saudi customer-service speech: 749 MSA, Najdi, Hijazi and entity-heavy sentences, five text
conditions, wideband and G.711 telephone audio, three ASR systems, paired statistics.

**Main findings.** The effect is model-dependent: catastrophic for the Habibi (F5-TTS) models, mildly harmful for
OmniVoice, Lahgtna and Chatterbox, helpful only for XTTS-v2. Removing case endings recovers most of the harm; for
OmniVoice, keeping the voice prompt's transcript undiacritized removes it entirely. Spelling out phone and ID numbers
matters far more than diacritics.

## Contents

| Path | What |
|---|---|
| `testset/testset.jsonl` | the 749 sentences with register, sub-dialect, domain, number form and entity types |
| `testset/diac.jsonl` | the same sentences in all five text conditions (`cond_raw`, `cond_catt_full`, `cond_catt_nocase`, `cond_shadda_only`, `cond_ft_full`) with per-sentence diacritizer latency |
| `testset/msa.txt`, `dialect.txt`, `make_entities.py` | sources the test set is built from |
| `results/clips.csv` | one row per clip x ASR x channel (96,872 rows): transcript, CER (capped at 1.0) and uncapped `cer_raw`, entity accuracy, UTMOSv2, DNSMOS, speaker similarity, duration |
| `results/paired_tests.csv`, `summary.csv` | paired tests per model x ASR x channel x register |
| `results/numbers.json` | every number quoted in the paper, generated by `code/make_tables.py` |
| `results/latency/` | CATT latency on CPU (8 and 1 threads) |
| `voices/voices.json` | the four reference voices (ids into the public Habibi SAU test split) and their prompt transcripts per condition |
| `code/` | the full pipeline (stages `s01`-`s07`), TTS adapters, table and figure generators |

Synthesized audio is **not** included: several TTS models and the reference voices carry non-commercial licences. It can
be regenerated with the code below.

## Reproduce the tables and figures (no GPU needed)

```bash
pip install pandas numpy scipy matplotlib
python code/make_tables.py --root . --out paper_tables
python code/make_figures.py --root . --out paper_tables
```

## Re-run the whole study

1. `./download_models.sh` fetches every model at the exact revision used in the paper.
2. `python code/get_voices.py` re-creates the four reference voices from the public benchmark (sample-identical).
3. Create one Python environment per system (they have conflicting dependencies) and set the `PY_*` variables listed at
   the top of `run_all.sh`; then run `./run_all.sh`.

Hardware used: one 24 GB GPU. omniASR-LLM-7B needs about 17 GB of GPU memory in bf16.

## Journal-length analyses

`code/p1_extra.py`, `p1_extra2.py`, `p1_extra3.py` and `p1_extra4.py` produce the additional figures and tables of the
journal versions (CER distributions, recognizer and channel agreement, case-ending analysis, voices and domains,
diacritizer comparison, complete paired tests). Run each with `--root . --out paper_tables`. The generated tables,
figures and number macros used by the manuscripts are in `paper_tables/`.
